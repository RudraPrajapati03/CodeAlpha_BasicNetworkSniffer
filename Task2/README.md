# Network Intrusion Detection System (NIDS)

**Internship:** CodeAlpha Cyber Security Internship — Task 2  
**Engine:** Suricata 8.0.7  
**Platform tested:** Windows with Npcap

## Overview

This project demonstrates a Network Intrusion Detection System using Suricata. Suricata monitors packets on a selected network interface and writes alerts when traffic matches configured rules.

The custom rule in this project detects ICMP Echo Requests (commonly generated by `ping`). This demonstrates packet capture, rule matching, and alert logging. It is a learning demonstration, not a complete attack-detection rule set. ICMP ping is normal traffic and is not inherently malicious.

## Custom rule

```suricata
alert icmp any any -> any any (msg:"NIDS TEST - ICMP traffic detected"; itype:8; sid:1000001; rev:1;)
```

## Configure paths on Windows

Open PowerShell as Administrator if needed. Update the project path and Npcap interface identifier for your computer; the interface identifier can change.

```powershell
$base = "$env:USERPROFILE\Desktop\New start\Codeapha\NIDS"
$env:Path += ";C:\Windows\System32\Npcap"

& "C:\Program Files\Suricata\suricata.exe" -T `
  -c "C:\Program Files\Suricata\suricata.yaml" `
  -S "$base\rules\local.rules" `
  -l "$base\logs" `
  --set default-rule-path="C:\Program Files\Suricata\rules" `
  --set threshold-file="$base\threshold.config"
```

Expected validation message: `Configuration provided was successfully loaded. Exiting.`

## Start live detection

Replace the Npcap device identifier below with the correct interface identifier on your machine.

```powershell
$base = "$env:USERPROFILE\Desktop\New start\Codeapha\NIDS"
$env:Path += ";C:\Windows\System32\Npcap"

& "C:\Program Files\Suricata\suricata.exe" `
  -c "C:\Program Files\Suricata\suricata.yaml" `
  -S "$base\rules\local.rules" `
  -l "$base\logs" `
  --set default-rule-path="C:\Program Files\Suricata\rules" `
  --set threshold-file="$base\threshold.config" `
  -i "\Device\NPF_{REPLACE-WITH-YOUR-NPCAP-INTERFACE-ID}"
```

Keep this terminal open while testing. In a second PowerShell window, ping your own local gateway (replace the address if it changes):

```powershell
ping -n 3 10.53.164.83
Get-Content "$base\logs\fast.log" -Tail 10
```

Expected: recent alerts containing `NIDS TEST - ICMP traffic detected`.

## Refresh the CSV summary

After the helper script is copied into this project, run:

```powershell
$base = "$env:USERPROFILE\Desktop\New start\Codeapha\NIDS"
powershell -ExecutionPolicy Bypass -File "$base\scripts\summarize-fastlog.ps1"
Import-Csv "$base\alert_summary.csv" | Select-Object -First 5 | Format-Table -AutoSize
```

Review the CSV before sharing it because it may contain local IP addresses.

## Test HTTPS connectivity

```powershell
curl.exe -I --max-time 15 https://example.com
```

A successful HTTP response confirms connectivity only. Because the custom rule matches ICMP Echo Requests, this HTTPS request is not expected to trigger that specific rule.

## Logs

- `fast.log`: human-readable alert entries.
- `eve.json`: structured events, if enabled in the Suricata configuration.
- `alert_summary.csv`: generated summary of matching alert entries; it is not committed by default.

## Limitations and safety

- This rule detects ICMP Echo Requests only; it does not identify every intrusion.
- Alerting is not blocking: this setup does not automatically stop traffic.
- Test only on devices and networks you own or are authorized to monitor.
- Do not publish raw logs or packet captures without reviewing them for IP addresses, identifiers, and other sensitive environment data.
