# Task 4 — Network Intrusion Detection System (NIDS)

**Internship:** CodeAlpha Cyber Security Internship — Task 4  
**Engine:** Suricata 8.0.7  
**Platform tested:** Windows with Npcap

> This project remains in the existing `Task2/` directory to preserve links. The official CodeAlpha task number is Task 4.

## Overview

This project demonstrates a rule-based NIDS using Suricata. It monitors a selected network interface and writes alerts when traffic matches configured rules.

The included custom rule detects ICMP Echo Requests (commonly generated by `ping`). This is a controlled test rule: ping is normal traffic and is not inherently malicious. This is a learning demonstration, not a complete attack-detection ruleset.

## Custom rule

```suricata
alert icmp any any -> any any (msg:"NIDS TEST - ICMP traffic detected"; itype:8; sid:1000001; rev:1;)
```

## Configure paths on Windows

Open PowerShell as Administrator if needed. Set `$base` to the actual local path of this project, and adjust Suricata paths if your installation differs.

```powershell
$base = (Get-Location).Path
$env:Path += ";C:\Windows\System32\Npcap"

& "C:\Program Files\Suricata\suricata.exe" -T `
  -c "C:\Program Files\Suricata\suricata.yaml" `
  -S "$base\rules\local.rules" `
  -l "$base\logs" `
  --set default-rule-path="C:\Program Files\Suricata\rules" `
  --set threshold-file="$base\threshold.config"
```

Expected validation message: `Configuration provided was successfully loaded. Exiting.`

## Start live detection

Replace the Npcap device identifier with the correct identifier for your computer. It can change between systems.

```powershell
$base = (Get-Location).Path
$env:Path += ";C:\Windows\System32\Npcap"

& "C:\Program Files\Suricata\suricata.exe" `
  -c "C:\Program Files\Suricata\suricata.yaml" `
  -S "$base\rules\local.rules" `
  -l "$base\logs" `
  --set default-rule-path="C:\Program Files\Suricata\rules" `
  --set threshold-file="$base\threshold.config" `
  -i "\Device\NPF_{REPLACE-WITH-YOUR-NPCAP-INTERFACE-ID}"
```

Keep this terminal open while testing. In a second PowerShell window, ping your own local gateway:

```powershell
ping -n 3 YOUR_GATEWAY_IP
Get-Content "$base\logs\fast.log" -Tail 10
```

Replace `YOUR_GATEWAY_IP` with the current gateway address on your own network. Expected: recent alerts containing `NIDS TEST - ICMP traffic detected`.

## Refresh the CSV summary

Run after alerts have been generated:

```powershell
powershell -ExecutionPolicy Bypass -File "$base\scripts\summarize-fastlog.ps1"
Import-Csv "$base\alert_summary.csv" | Select-Object -First 5 | Format-Table -AutoSize
```

Review the CSV before sharing it because it may contain local IP addresses.

## Response and limitations

The project generates alerts; it does not automatically block traffic. Follow the response playbook to review and escalate alerts. Treat a ping alert as informational unless independent evidence supports a different assessment. Any containment action must be performed by an authorized administrator under an approved procedure.

The current custom rule detects ICMP Echo Requests only; it does not identify every intrusion. Test only on devices and networks you own or are authorized to monitor. Do not publish raw logs or packet captures without reviewing them for sensitive details.
